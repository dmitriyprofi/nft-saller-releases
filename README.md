# NFT saller releases

Public **release-only** distribution channel for **NFT saller**.

This repository intentionally contains no application source code, private keys, wallets, API credentials, databases, user data, internal logs or development secrets.

## Repository role

This repository is **not** a second source repository and is not used to determine application logic or development state.

Canonical source, tests and private project documentation live in the private source repository `dmitriyprofi/nft-business`.

The normal `main` branch here should stay minimal. Release binaries belong in GitHub **Releases**, not in source history.

## Channels

- `beta` — owner-first testing channel.
- `stable` — employee/default channel after owner verification.

A version promoted from `beta` to `stable` must use the **same exact installer bytes and cryptographic hashes**. Do not rebuild between owner acceptance and stable promotion.

## Release assets

Each channel release contains the exact Electron/NSIS update trio produced and pinned by the private source build:

- installer `.exe`;
- matching `.blockmap`;
- `latest.yml`.

Asset names must exactly match the updater metadata generated by the accepted build.

The application verifies updater metadata/checksum before installation. Release identity/checksum pins are maintained in the private source repository.

## Publication rule

Use an **authenticated GitHub Releases upload mechanism** that can publish the already-built pinned assets and then verify the public asset names/metadata.

Do not:
- commit large installers or chunked installer parts to `main` merely to move binaries;
- rebuild an already accepted artifact just because the current tool cannot upload it;
- create a parallel source tree here;
- publish source archives from the private project.

A previous temporary git-push publishing workflow was intentionally removed from `main`. This README no longer describes that retired mechanism as current infrastructure.

If a future automated publishing workflow is introduced, it should be a separate reviewed release-infrastructure change with least-privilege permissions and must preserve exact pinned bytes.

## Security

Never publish here:
- application source;
- private keys / seed phrases;
- wallet credentials;
- OpenSea/API credentials;
- GitHub tokens;
- local databases or runtime state;
- logs containing secrets;
- owner/employee personal data.

Public release artifacts should contain only distributable application/update material intended for end users.
